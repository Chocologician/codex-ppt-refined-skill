# 项目目录、讲稿与组装

建立目录、写讲稿、组装或交付前阅读。适用于图片式制作；可编辑分支按其独立验收规则交付。

## 目录

项目目录中区分 origin_image/ 最终页图、assets/ 源素材、prompts/ 单页任务、deck_spec.json、outline.md、speech.md、slide_jobs.json 与 slide_run_state.json。草稿和失败变体不混入最终页图。

未指定输出位置时使用当前工作区或源文件所在目录。组装脚本的项目文件夹名需要与成品文件名对应：

    python {skill_root}/scripts/run_skill.py assemble {base_dir} {deck_name}.pptx --init
    python {skill_root}/scripts/run_skill.py assemble {base_dir} {deck_name}.pptx --aspect-ratio 16:9

base_dir 为 deck_name 文件夹的上一级。脚本从其 origin_image/ 中读 slide_01.png 等最终图片，输出到项目目录。实际参数以脚本帮助为准。

## 逐页质检

核对内容与大纲、中文乱码、字号与截断、素材保真、视觉一致性及重要对象遮挡。不要求的页码、标志或水印不擅自添加。严重失败重生成，局部问题用已选择后端编辑，检查通过后才替换。

## 讲稿

speech.md 写可直接讲述的稿件，而非屏幕文字摘要。用最终大纲逐页对应，按受众选择解释方式：技术说明注重因果与例子，科研注重方法和证据，短答辩注重个人贡献与条件匹配。

全篇按讲述总时长分配，不机械要求每页固定字数。先说结论，再解释视觉，必要时自然过渡；不写“本页主要介绍”等空泛套话，不写制作过程评论。

现有组装脚本支持 Slide N 和“第 N 页”两种页码标题。中文讲稿可以直接使用：

    ## 第 1 页：开场
    各位老师好……

    ## 第 2 页：内容结构
    下面从三个方面汇报……

speech.md 存在且标题可识别时，脚本将对应内容写入PPT备注。录音前只能估计时长，不能用字数算出“准确三分钟”。

## 组装条件

所有预期页图齐全且命名、顺序正确；认可样张 accepted，其余任务 recorded。还有 pending、dispatched 或 blocked 时不宣布完整成品。用状态脚本检查，不手改状态。

运行依赖缺失时使用 run_skill.py bootstrap 安装，后续继续通过统一入口运行，确保解释器一致。接口诊断仅用于真实后备故障，不在纯本地组装时无故调用。

## 交付

核验真实路径、有效文件与必要备注，简短提供成品和使用限制。保留内部来源、状态和检查证据，用户需要时再提供。复杂任务可报告实际页数、后端与未完成原因，不能将阻塞稿称为完成。

用户愿意复用自定义视觉时，可按[风格库](style-library.md)保存。不保存私人内容，不在一次性任务中擅自改公共风格。

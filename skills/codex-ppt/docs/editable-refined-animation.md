# 可编辑重建与精编动画延伸

用于已认可视觉风格的图片/PDF稿、可编辑PPT的精编动画，以及“太快/太慢”的调整。延续已认可设计，不重新要求确认提纲、模板或生图后端。

## 起点与源文件

| 当前输入 | 起点 |
| --- | --- |
| 图片/PDF稿，要求可编辑 | 按参考重建，再逐页校准 |
| 可编辑稿，要求匹配参考 | 校准差异 |
| 已校准PPT，要求动画 | 清点组件，设计动画 |
| 已有动画，只改速度 | 保留效果和分组，调整等待与时长 |
| 明确指定最终文件 | 该路径是唯一内容依据，不猜其他版本 |

记录源文件真实绝对路径、SHA256、页数、隐藏页、画幅、字体、讲述总时长和保留素材。候选文件放私有构建目录，保留原始素材与交付版本。

使用当前环境演示文稿技能/工具完成原生重建与验证，遵循适用的创建标记和交付流程。运行时通过依赖发现工具定位；不硬编码这次项目的机器路径和版本。

## 1. 可编辑重建

- 标题、正文、数字、流程节点、连接线及需要编辑的图表采用原生对象。照片、原始网络图、邮件、证书和标志沿用图片。整页底图加透明热区不算可编辑。
- 锁定画幅、参考页映射、字号、换行、文字框宽度、图片裁剪、组件尺寸与对齐。用户指定字体时覆盖组内文字。
- 保留参考色彩、层级、留白。院徽、橙蓝配色、微软雅黑仅在用户要求时使用，不成为所有项目默认。
- 不在动画阶段擅自修改文字、移动组件或更换标志。缺少新视频时不自行嵌入旧视频。

## 2. 校准与冻结

同一渲染器、同一分辨率逐页导出对照，检查字体、尺寸、换行、裁剪、徽标、留白、溢出与层级。PDF与PPT跨渲染器差异用并排图人工检查，不要求逐像素相等。

校准通过后保存独立基准PPTX、各页渲染及哈希。之后只改动画，以此为基准。形状ID、索引只对应产生清单的确切源文件；内容或分组变化后重新读取。

## 3. 组件与分组

清单包含形状ID、名称、类型、坐标尺寸、文字摘要、组关系、已有动画和隐藏状态。按语义与视觉关系组织组件，不按每个文本碎片加动画。

清点已分组稿时递归读取组内文字与子对象，保留层级和Z序。用于执行计划的shapeIds仍只能来自顶层，不能把组内ID误传给顶层选择器。

组件例子：排名及说明、奖项及说明、方法节点、节点之间的箭头、职责、证据及说明。组名使用“专业排名”“训练验证”“投稿证据”等语义名。

标题、栏目标识、标志通常静态；封面和结尾可例外。流程按依赖方向展开，先来源后分支，结果与贡献适当后置。一张不透明网络图片只能作为图片进入，不伪装成多个可编辑模块。

优先复用已有合理分组。新分组可能改变Z序和索引，使元素被遮挡；完成后必须重渲染对比。使用当前清单的ID或唯一名称，不在分组后继续使用旧索引。

某些编辑器导出时会锁定形状组合。分组失败要说明具体页与组件，先核对源对象限制，不擅自解除用户设置。公开示例的源稿由项目创建并允许组合；其他文件不保证同样的权限。

## 4. 精编动画与张弛

设计感来自阅读顺序、节奏和停顿。优先淡入，箭头定向擦除，重点数字可轻微淡入缩放。避免逐字飞入、旋转、弹跳、过量缩放和多方向乱动。

短答辩可采用“进入页后自动展开，讲完单击翻页”。用户要手动控制时，按语义段落设置点击，不让碎片各占一次点击。未要求不强制自动翻页。页间转场与页内进入分开设置。

先按讲述时间分配进入窗口，留完整画面阅读时间。下表仅是短答辩初始参考，不是硬性标准：

| 页角色 | 全部呈现参考 |
| --- | --- |
| 封面/结尾 | 1.5–2.5秒 |
| 目录 | 2–3.5秒 |
| 学业/竞赛/集体事务 | 4–6秒 |
| 架构/科研证据 | 5–8秒 |
| 多节点工作流 | 8–10秒 |

单个对象可先用0.4–0.65秒，箭头约0.25–0.4秒。重点排名之间、证据出现后留停顿，同层级次要信息紧凑些。20秒讲述页不必花20秒才呈现完整。依据内容与用户反馈调整。

### 调速迭代

- 区分单个效果运动速度与信息间隔。运动调duration，间隔调gap。
- “太快”优先增加关键组阅读间隔，适当增加duration；“太慢”优先缩短gap，少量缩短duration。
- 初次反馈可将间隔调整约15%–30%。已有过快版和过慢版时，从两版有效时间取中间档，不再次翻倍。
- 不把所有duration、gap机械乘同一系数。记录每页旧→新展开时间，实际放映检查。

### 可审阅计划与COM时序

保存JSON：源文件inputSha256，每组标签、shapeIds、effect、绝对开始start、持续duration及可选direction。不混用绝对秒数和相对delay。

串行AfterPrevious=3时，previousEnd初值为0：

    delay = start - previousEnd
    previousEnd = start + duration

start不能早于上一组结束。重叠动画需要另行建立并验证并行时间结构，不能把不同触发模式下的delay都视作页内绝对时间。

COM效果枚举不是OOXML presetID，不互换。MainSequence.Count用于效果计数，不只数p:animEffect，缩放等效果可能用其他节点。

先设方向及缓动，再写duration与delay，并回读核对；部分效果设置方向会重置时长。PowerShell使用Math.Max计算小数gap时显式选择double重载，避免整数0使小数间隔取整。保存后重开确认真实时间，不仅凭计划JSON报告已实现的秒数。

Windows桌面PowerPoint可使用 scripts/apply_refined_animations.ps1 辅助清点及执行串行动画。环境缺少PowerPoint时，不假称网页预览能完整验证原生效果。复杂媒体、交互触发、退出/并行动画使用目标应用另行实现。

## 5. 验收

1. 检查可编辑性、全文、页数、隐藏页、字体、标志、媒体以及各动画对象、顺序、触发、时长。
2. 同一渲染器导出完成状态，与冻结基准逐页比较。只改动画应无视觉变化；若不同，检查分组Z序、位置与字体。静态像素一致不证明动画正确。
3. 在目标桌面PowerPoint实际放映，或用CreateVideo输出足够长预览。每页覆盖最大动画结束时间，再留1–2秒完整状态；检查是否包含隐藏页。预览不等于答辩计时。
4. 至少检查封面、重点数字、密集流程、科研证据和结尾。复杂流程抽取多个时间点，检查全空、遮挡、证据一闪而过、末尾贡献未出现即翻页等问题。
5. 无目标应用时明确实际验证范围，不宣称已验收放映，不交付静态图冒充动画版。

## 6. 可靠交付

从工作区解析真实绝对路径，不拼写猜测用户目录。finalizer要求真实父目录时先创建最终目录；回执放构建目录，不与成品混放。

核验最终文件存在、大小非零、ZIP可读并通过当前环境包/布局检查。交付副本与已验证文件哈希一致。只链接已检查的真实路径。用户需要时复制成品到根目录，保留原文件，避免把复制当作移动。

简短交付PPT、必要预览、放映操作和使用限制。默认不向用户堆源码、审计与临时文件。

若用户说文件没了，核查实际路径、旧链接及目录内容，再判断是链接错误、目录不符还是文件缺失。不先断言动画隐藏，更不覆盖用户指定最终版本。

## 7. 讲稿衔接（按需）

从用户指定的最终PPT重新读取逐页内容。区分个人承担、团队成果、计划与已完成，在投不写成发表。按总时长分配稿长，不机械套每页150–400字。

口述顺序匹配动画，给证据留阅读时间。录音前只说预计时长。评委复核看个人贡献、证据、奖项条件覆盖与追问。可补用户确认但未上屏的事实，不擅改冻结PPT。

## 执行器用法

清点现有对象：

    ./scripts/apply_refined_animations.ps1 -Mode inspect -SourcePath <source.pptx> -ReportPath <inventory.json>

最小计划（shapeIds来自当前清单）：

    {
      "inputSha256": "<actual SHA256>",
      "slides": [{
        "slide": 1,
        "groups": [
          {"label":"主题", "shapeIds":[2], "effect":"fade", "start":0.1, "duration":0.5},
          {"label":"核心信息", "shapeIds":[3,4], "effect":"fade", "start":1.0, "duration":0.55}
        ]
      }]
    }

执行：

    ./scripts/apply_refined_animations.ps1 -Mode apply -SourcePath <source.pptx> -PlanPath <plan.json> -OutputPath <new-candidate.pptx> -ReportPath <audit.json>

默认拒绝覆盖源页已有动画；确实要重编时加-ReplaceExisting。未列在计划中的页面保持原状。仅调速时优先改已有Timing，不重新分组。执行器只支持顶层形状、串行进入，不支持嵌套组内选取、重叠、退出、媒体与触发器动画。

空slides、空groups及非整数ID应拒绝，不能把空计划解释为清除动画。执行器保存后会重开核对动画时序与隐藏页，但仍不代替视觉和播放验收。源动画包含执行器不支持的类型时，不静默替换成淡入；保留源效果并使用目标应用处理，仅限明确的新方案测试可重新指定效果。

官方API：[触发类型](https://learn.microsoft.com/office/vba/api/PowerPoint.MsoAnimTriggerType)、[效果枚举](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.msoanimeffect)、[AddEffect](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.sequence.addeffect)。

## 修改执行器后的自动回归

运行 scripts/test_refined_animations.ps1，可用-WorkDirectory指定独立构建目录。它只生成合成测试稿，自动检查分组文字、淡入/缩放/擦除、保存后时序、隐藏页、最终静态像素、源文件哈希与11类错误计划拒绝。结果写入每次新建的独立子目录。

真实稿进一步测试时，用副本覆盖多页多组件和实际PowerPoint视频；原稿哈希保持不变。结构和时序自动通过不等于审美已被证明，也不代表已覆盖图片重建、所有并行动画或所有办公软件。

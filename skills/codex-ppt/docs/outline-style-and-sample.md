# 大纲、风格与样张

写大纲、提供视觉方案或制作样张前阅读。保存可复用风格另见[风格库](style-library.md)。

## 大纲

每页记录页码、标题、主要事实、页面角色、视觉意图，以及必须使用的图片路径和用途。角色可包括封面、目录、背景、过程、对比、数据、架构、结论等，不强行重复一种构图。

明确项目目录后保存 outline.md；目录未定时先展示，确定后及时落盘。必需图表使用 Markdown 图片引用并标注严格输入与保真要求，让用户核对具体素材。已有相关批准不重复设置门槛；否则大纲认可前不进入风格、后端、样张或最终任务。

## 提取与确认风格

用户已给风格或参考稿时，先渲染、查看代表页，再提取视觉规则，不强制用户重新从几个方向中选择。不要仅凭文件文字、XML或对象结构推测视觉风格。区分“复用视觉”与“复用内容”，后者需要任务依据。

没有明确方向时提供少量具体选项，说明配色、构图、字体层级、素材处理和留白。全篇保持视觉身份，但按页面语义变化构图；layout_blueprints 只是候选起点。

参考库分两类：技能 references/ 下的内置文件，以及共享运行目录 references/ 下的个人文件。先扫描个人目录并合并，同名个人文件优先，不把私人风格登记到技能安装目录。用参考启发设计，而非每页套同一个模板。

## 样张

大纲、风格和后端确定后，先生成一页有代表性的内容样张；尽量不只用封面，因为正文更能检验信息密度和中文质量。

直接保存为该页最终 slide_XX.png 文件，展示后核对风格、排版密度、字体与文字。认可后复用，不在 origin_image/ 另放 sample_slide.png；修改时先修同一页样张，不擅自开始全篇。

认可后在 deck_spec.json 写入 sample_generation_method，再准备任务。至少记录：

- backend_used、tool_name、mode：实际后端、工具和生成/编辑方式。
- prompt_source：样张提示来源。
- 后端暴露时的模型、尺寸和质量；不知道的值不编造。
- approved_sample_path：认可页图的绝对路径。
- input_context_preparation：参考素材如何被查看或传入。
- handoff_rule：工作者沿用该方法，缺失能力时报阻塞而不是换低质量方法。

其他页面把样张作为风格参考，而非必须照抄的布局。内置风格列表直接从 references/ 扫描，新增公共风格经仓库贡献流程评审。

# 快速开始

本项目有两类使用方式：让 AI 代理执行工作流；在明确环境中直接运行脚本。两者不混为一个“一键生成”命令。

## 先验证一个固定例子

不熟悉形状编号、计划格式或生图后端时，先运行公开动画示例：

    ./examples/public-demo/run_demo.ps1

条件为 Windows、PowerShell 7 与桌面版 Microsoft PowerPoint。预期得到新的构建目录，包含 animated.pptx 和 audit.json。用 PowerPoint 按 F5 放映。无需图片服务，不修改源稿。

完整资料见[公开示例](../examples/public-demo/README.md)。这条路径验证原生动画，不验证图片生成或图片转可编辑。

## 用代理从零制作

1. 下载或克隆仓库，将 skills/codex-ppt 文件夹整体放到目标项目的 .agents/skills/codex-ppt。
2. 让支持该目录约定的代理读取技能；其他代理按其技能发现方式配置，不保证路径完全一样。
3. 提供资料、受众、页数、讲述时长、需要保留的图表、是否必须可编辑及是否需要动画。
4. 先确认内容与风格，生成一页代表性样张，再扩展全篇。
5. 图片式稿的每页是一张图片。需要编辑时，再用代理实际可用的原生编辑工具重建并校准；本仓库不附带独立转换引擎。
6. 动画之前保留可编辑基准稿。代理清点对象、写计划，执行后核对画面与放映。

预期产物依模式不同：图片式为逐页图片和组装PPT；原生重建为可编辑基准稿；动画阶段为新候选PPT、时序记录与必要预览。中间文件不是全部都应交付给最终观众。

可以先把[合成内容提纲](../examples/public-demo/brief.md)交给代理练习。生成工具不同，结果不保证与公开原生示例相同。

## 图片式命令行：统一解释器

在仓库根目录运行：

    python skills/codex-ppt/scripts/run_skill.py bootstrap

这会在共享目录创建独立环境并安装图片式依赖。之后必须通过同一入口运行依赖这些库的命令：

    python skills/codex-ppt/scripts/run_skill.py image-gen --help
    python skills/codex-ppt/scripts/run_skill.py assemble --help

不是直接用任意系统 python 执行底层生图或组装脚本。统一入口会选择共享环境的解释器，不会隐式安装依赖。

可通过 CODEX_PPT_HOME 指定共享目录。配置接口时使用：

    python skills/codex-ppt/scripts/run_skill.py config --help

只在有意使用图片服务时配置真实凭据。示例动画、静态测试不需要密钥。内置生图通常由宿主工具管理，不通过这个Python入口调用。

诊断默认不发起真实接口请求：

    python skills/codex-ppt/scripts/run_skill.py doctor

需要真实接口排查时再明确添加 --check-api。要确认将使用哪个解释器而不执行操作：

    python skills/codex-ppt/scripts/run_skill.py --show-command assemble --help

安装后的技能目录相对路径不同，应相应替换脚本路径；入口会根据自身位置找到同目录脚本。

## 常见情况

- 找不到技能：先核对代理的技能发现目录及同名冲突。
- 没有生图工具：选择实际可用的后端，或仅验证原生示例，不伪造生成结果。
- 只有图片、不能改字：图片式产物本来不能逐对象编辑，需要原生重建步骤。
- PowerPoint网页预览不播动画：使用桌面版核验，不从网页行为推断文件内容消失。
- 源文件哈希不匹配：源稿已变化，重新清点并建立计划，不关闭校验强行套用。
- 缺少Python依赖：先运行统一入口的 bootstrap，然后仍通过统一入口执行。
- 需要更精确的环境信息：查看[环境兼容性](环境兼容性.md)及公开示例的核验记录。

# 发布与上游同步

## 版本

使用主版本、次版本、修订号区分变化。早期迭代中，修复用修订号，增加兼容功能用次版本；破坏性格式或默认行为变化明确写迁移方法。路线图不等于发布承诺，更新记录只写已完成内容。

## 发布前

1. 确认改动范围、来源、许可和文档。
2. 更新版本记录与来源清单。
3. 运行仓库检查，涉及动画时运行本机合成稿回归。
4. 对代表页做视觉与放映检查。
5. 从干净副本检查技能可完整复制，移除个人材料、凭据和缓存。
6. 有权限维护者创建标签及发布记录，写明环境与限制。

发布属于显式操作；文档与测试不会自动推送、公开发布或上传素材。

## 上游同步

选择上游具体提交或版本，阅读变化，逐文件对照本地。将上游更新与本地扩展分开，保留作者和许可。

最初安装提交未知，不能声称一次比较找回了完整历史。将来已核实的同步可以记录具体提交，但不能反推未知来源。

同步后更新来源、校验值、中文说明与测试。上游能力与本地扩展重叠时，写明保留、替换或迁移理由，避免两份冲突规则。

# 架构与扩展

| 层次 | 位置 | 责任 |
| --- | --- | --- |
| 入口 | 首页与技能入口 | 引导选模式，不塞入所有细节 |
| 工作流 | 技能下 docs/ | 内容、素材、视觉、校准、动画与交付 |
| 风格 | 技能下 references/ | 可复用视觉规则，不含私人内容 |
| 执行 | 技能下 scripts/ | 后端、状态、原生操作 |
| 维护 | 根目录 scripts/、tests/、.github/ | 来源、测试、协作与版本 |

图片式生产与原生动画分开执行，共享事实与视觉目标，但不共享所有工具限制。新增模块不能让一条路径被另一条无关规则阻断。

## 增加工作流模块

1. 说明何时使用、何时不使用。
2. 写清输入输出、依赖与保持不变的内容。
3. 细节放独立文档，从技能入口按需引用。
4. 重复、确定性操作才提炼脚本，说明关键失败如何处理。
5. 给合成或公开示例与可观察验收标准。
6. 更新来源与测试，确认复制整个技能目录后仍可使用。

安装后的技能不能依赖仓库根目录文档才能制作；根目录负责维护，技能目录负责运行。

## 增加风格与后端

共享风格需要来源和评审。用户个人风格放安装目录之外，更新时不覆盖。技术字段保持兼容；上游风格中的英文生图描述是原始提示词资产，翻译应单独提交并验证，不与维护文档翻译混合。

新后端或执行器先做可选实现，写清平台与能力。配置来自环境或既有机制，不写死本机路径与密钥，不静默切换模型、服务或效果。字段及默认行为变化说明兼容性与迁移方法。

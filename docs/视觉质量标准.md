# 视觉质量标准

代码运行只是起点。评审应同时看内容能否读懂、画面是否协调、证据是否准确、是否适合讲述。

## 比较条件

相同内容、画幅、渲染工具与输出尺寸下对比。风格覆盖封面、普通正文和复杂流程或数据页，不能只靠封面证明整套效果。

| 维度 | 要检查的问题 |
| --- | --- |
| 层级 | 能否快速找到标题、结论和证据？字号与字重是否有明确角色？ |
| 版式 | 对齐、边距、留白是否合理？是否机械重复卡片？ |
| 中文 | 是否乱码、断词、行距过密、字号过小或标点拥挤？ |
| 配色与素材 | 强调是否克制、对比是否足够、标志是否变形、图表是否忠实？ |
| 全篇 | 是否保持统一风格，同时允许不同内容改变构图？ |
| 编辑 | 需要修改的部分是否原生？改字是否破坏布局？ |
| 动画 | 顺序是否符合逻辑，重点是否有辨认时间，完整状态是否留得住？ |
| 事实 | 是否区分个人与团队、计划与已完成？ |

## 如何反馈与合并

写具体症状、影响和建议，例如“正文和注释字重相近，难找结论，建议拉开层级”，而非只说“更高级”。各维度可记录通过、需修改、不适用，并附证据，不用无依据的综合分数代替判断。

不牺牲事实和可编辑性制造表面效果。存在主观差异时说明适用场景，先作可选风格；乱码、内容遗漏、严重溢出或数据改变先修复后交付。
